## For future agents

Hooks live in `hooks/hooks.json` and run `labbrain hook <event>`; they exit only 0 or 2 and
never print a decision. The Bash rules are in `labbrain/hooks/bash.py`, the spec is
`docs/superpowers/specs/2026-10-20-lab-brain-hooks-design.md` (section 14 holds the rulings).

## Context

Up to M4 the vault rules were enforced only after the fact, by lint, pre-commit and permission rules that match path text. M5 stops a breaking tool call while the agent works: a read of protected data, a rewrite of a frozen note, PHI written into a note. The hooks run on every tool call, so they must be fast, and a guard that fails open or leaks while blocking is worse than none.

Platform facts, from real headless runs:

- **Claude Code 2.1.284** (2026-10-20). PreToolUse and PostToolUse payloads carry `tool_name`, `tool_input`, `cwd`, `session_id`, `permission_mode`, `transcript_path`, `tool_use_id` and `hook_event_name`; PostToolUse adds `tool_response` and `duration_ms`; SessionStart adds `source`. Read sends `{file_path}`, Write `{file_path, content}`, Edit `{file_path, old_string, new_string, replace_all}`, Bash `{command, description}`. The recorded payloads are in `tests/fixtures/hooks/`.
- Exit 2 blocks a PreToolUse call and shows stderr to Claude; any other non-zero exit lets the call proceed. A shell-form `<engine> hook … || exit 2` whose engine is missing blocked both Read and Bash.
- `onFailure: "block"` (2.1.295 or later) also blocks on timeout and on start failure. 2.1.284 tolerates the key. Without it, a timed-out PreToolUse hook lets the call proceed.
- Hooks run in parallel and deny wins; plugin hooks merge with settings hooks. Plain stdout from SessionStart on exit 0 enters the context. Each payload's `cwd` follows `cd`, so the guard needs no per-session cwd state.
- `--bare` skips hooks, so the hooks smoke tests run without it.
- 2.1.284 had no Glob or Grep tool: the agent searched through Bash. **Claude Code 2.1.304** does have Glob. It runs `rg --files --null --glob <p> --sort=modified --no-ignore --hidden`, without `--follow`. It splits an absolute pattern at the first `*?[{`, rewrites overlapping leading components, and resolves `..` textually.
- Warm latency: `uvx --from <plugin root> labbrain --version` about 70 ms; importing `labbrain.vault` (pydantic) about 100 ms.

## Decision

- **Hooks live in the plugin** (decided 2026-10-20), in `hooks/hooks.json` next to `skills/`, so they are versioned and pinned with the engine. One engine entry point per event: `labbrain hook pre-tool-use`, `post-tool-use` and `session-start`. One pre-tool-use process runs the data guard, self-protection, the frozen-file guard and the PHI pre-scan. The template's permission deny rules stay as a second layer.
- **Fail closed.** The pre and post commands end in `|| exit 2`, and pre also sets `onFailure: "block"`. Bad or oversized input, any exception, and a broken vault config deny, with fixed messages and no traceback. A broken config allows only the Read tool on `.labbrain/`.
- **No `allow` output, ever.** Hooks deny with exit 2 or stay silent, so the user's own permission prompts still apply.
- **Messages never leak.** A denial names the rule and the `data_paths` entry as configured, never the command, a candidate path, a file name under a data path or file contents.
- **Two readings of every path.** Each path is judged physically (symlinks resolved first) and textually (`..` collapsed); either reading inside a protected root denies.
- **Glob is a recursive construct.** It is denied when a protected root is inside or under a search base: `path` or the cwd, the deepest literal directory before Claude Code's wildcard cut, and literal runs. A component starting with `!`, or a `\`, is denied. Glob and Grep also run the link-exposure walk.
- **Bash over-approximates.** Every word and path-like substring is a candidate; unbindable leading variables and substitutions are wildcards and deny; recursion from an ancestor of a root, or from a folder with a link into one, denies. The one literal substitution allowed is a whole word `"$(cat <<'EOF' … EOF)"` with a quoted delimiter, and only when every program is `git` or `gh` (no push, fetch or pull; not `gh repo` or `gh gist`), with no assignments, no CR, balanced parens, the literal not in program position, and nothing redefining programs. That keeps commit messages and PR bodies working.
- **Self-protection** in protected vaults covers `.labbrain/`, `.copier-answers.yml`, `.claude/settings*.json`, the plugin root and caches, MCP tools, `copier`, and nested agent CLIs.
- **Frozen baseline is git `HEAD`**, as in lint, using the shared `labbrain/frozen.py`; a note created this session stays editable until committed.

## Alternatives considered

Hooks in the template's `.claude/settings.json` (not pinned to the engine, and editable by the agent); a separate process per check (three engine starts per call); emitting `allow` for clean calls (skips the user's permission prompts); a Bash allow-list of known-safe commands (breaks everyday work); Claude Code's OS-level sandbox with data paths denied (also blocks training runs, so it stays the user's choice).

## Consequences

Without `uv`, every tool call in a session with the plugin enabled is blocked: loud, but closed. False positives are accepted: a differently cased path, a search from a parent of a data folder, or a command substitution next to a path is refused, and the message tells the agent to narrow the search or ask the user. Known gaps are listed in section 12 of the spec and in the README: code that prints records, obfuscated or encoded paths, MCP tools that write vault files, `git -C` with a pre-written repo config, and hard links.
